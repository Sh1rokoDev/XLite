# 限制与已知问题

## 协议

- 迅雷开放 SDK 仅支持 **HTTP/HTTPS**。不支持 BT/Torrent、磁力链、ed2k、FTP/FTPS/SFTP、Metalink。
- 不做直连 HTTP 兜底：**没有有效 API Key 就不能下载**。
- `thunder://` 只做本地 Base64 解码，解码后仍必须是 HTTP/HTTPS。

## SDK 能力

- 只提供全局限速；没有每任务独立限速。
- Java 层没有自定义 HTTP Header、事件回调、批量创建 API。
- 通过轮询获取状态，约有 1 秒延迟；暂停/继续/删除都是异步生效。
- 动态链接加速由官方默认开启，官方说明存在“极低概率下载文件与源文件不一致”的风险；XLite 在首次启用时提示，可随时关闭。
- 相同 URL + 相同保存目录的任务会被拒绝；需要重新下载时请先删除旧任务。
- 错误码 `111136` 表示连接目标服务器失败或长时间无数据，可能只对特定源出现（例如实测某清华镜像站，curl 正常但 SDK 无数据管道）。
- 文件名/路径冲突由 SDK 返回 `9403`；XLite 会预先计算不重复的文件名，并在批量添加时再次校验。

## 鉴权与安全

- 客户端直接保存 API Key 是迅雷官方 Demo/个人使用方式；生产分发应增加服务端签发登录 token，避免把长期 Key 交给客户端。
- Key 在本机加密（Windows DPAPI / Android Keystore / Linux 0600 文件），但无法防御已经控制设备的攻击者。
- App ID 从 JWT `aud` 自动解析依赖未文档化行为；解析失败时需在设置的高级选项手动填写。
- 日志会脱敏 Key、JWT 和常见签名参数，但仍应避免在反馈中粘贴完整日志之外的敏感信息。

## Android

- 仅构建 `arm64-v8a`，不包含 x86/x86_64，因此不能在本机模拟器运行。
- 迅雷 `libdk.so` 使用 4KB 对齐；Android 15/16 的 16KB page 设备可能无法加载，需要官方后续版本修复。
- 下载目录是应用专属外部存储，不支持 SAF 选择任意目录；卸载应用会删除下载文件。
- 后台下载受系统省电策略限制；前台服务与 wakelock 只能降低被中断的概率。
- 未做真机测试，仅完成编译与 APK 打包验证。

## Linux

- 仅 x64 桌面；使用 WSL 构建，未做实机 GUI 运行测试。
- 分发为单文件 AppImage，内置 Java；已在 WSL/Xvfb 检测到正常启动的 XLite 窗口。
- 首次下载可能需要授予文件执行权限。静态 runtime 无需另装 libfuse2，但仍依赖系统桌面图形库和 FUSE 支持；受限环境可用 `--appimage-extract-and-run` 自动释放启动。
- 系统主题跟随是 best-effort（优先 gsettings），失败时回退浅色。

## Windows

- Windows 分发为目录式便携 ZIP 和 MSI 系统安装包，均内置 Java。设置、任务、日志和临时文件位于程序目录，不向用户缓存目录释放运行环境。
- 便携包在构建时展开 SDK DLL；安装版 SDK 的临时加载位于安装目录 `data/tmp`。干净 Windows 环境的原生依赖仍需发布前复核。
- MSI 只向 `data/` 和 `downloads/` 提供普通用户写权限，程序二进制目录维持系统默认权限；升级与卸载保留用户数据。
- MSI 支持运行更高版本安装包升级，尚未实现在线自动更新。固定升级标识不得更改，发布时必须递增三段版本号。
- 打包与升级元数据已检查，尚未在本机实际安装/升级 MSI。详细规则见 [PACKAGING.md](PACKAGING.md)。
- 托盘依赖 AWT SystemTray；不可用时会禁用“关闭到托盘”。

## 界面与交互

- 每个任务的操作入口是卡片内的按钮与“更多”菜单，不支持仅悬停显示的隐藏控件。
- 暂不提供：浏览器扩展、云盘/账号体系、定时下载、自动更新、macOS 发布包。
- 迅雷官方 Logo 与品牌素材未使用；应用图标为自绘。
